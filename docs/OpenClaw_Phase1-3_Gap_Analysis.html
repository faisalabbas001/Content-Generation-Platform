1. Executive Summary

This report compares the two client requirement documents against the actual state of the OpenClaw codebase. The OpenClaw_TechDoc_v1.0 is treated as the authoritative contractual baseline — it explicitly states it is the "single source of truth for OpenClaw Phase 1 architecture" (§14.3) and defines the Phase Roadmap (§1.3). The OGZ_Simple document is a later "What We Built" narrative (June 2026, v2.0) describing an evolved creative direction (5 Creative-Director brains, a 3-model cross-compare, 94 visual chains, fal.ai); it is used here as a secondary reference and a source of intent for several Phase 2/3 items.

Headline findings:

  • Phase 1 is functionally delivered. All 31 BrandDNA / system tables, RLS & append-only policies, PDPL cascade, all 7 client screens, all 9 admin views, 3 Copilots, the full CEO→COO→DeepSeek→CCO→CEO AI chain, the 11 human-override triggers, the Memory Controller, and all 11 canonical n8n flows exist with evidence.
  • Two large architectural deviations from the TechDoc (both deliberate, documented in code): (1) the visual layer uses fal.ai, not the spec's Weavy.ai; (2) the CEO/COO agents run on OpenAI / DeepSeek, not the spec's Claude Sonnet 4.6 / Haiku 4.5 (Anthropic budget). Functionality is preserved; the contract text is not.
  • Genuine Phase 1 gaps: Stripe payments (stub returning HTTP 501), PostHog analytics (empty package), and a hard-coded-secrets problem in the n8n flows that violates security requirement SEC-02.
  • The OGZ_Simple "5 Creative Director brains / cross-compare / ALLaM 34B" system is not implemented as described; the code instead uses a deterministic composition_matrix of 6 creative methods plus a visual-chain library.

2. Methodology & Evidence Basis

Conclusions are drawn only from (a) the two requirement PDFs and (b) direct inspection of the repository. The audit covered:

  • Database: supabase/migrations/* (111 migrations), packages/db, sql/.
  • Frontend: apps/web/src/app (75 page routes, 70+ API routes), layouts, i18n.
  • AI agents: packages/ai/src/providers, packages/memory, prompts/.
  • Orchestration: n8n/flows (17 flow exports), packages/n8n.
  • Integrations & services: packages/{image,scraping,payments,email,vectors,analytics,compliance,pdpl}, services/{cio-analyzer,generation-worker,pdpl-janitor}.
  • Project record: CHANGELOG.md, which documents the deliberate architectural decisions cited below.
Note on the two documents. The TechDoc (April 2026) specifies Weavy.ai, Claude-based C-suite, DeepSeek captions and a single-caption pipeline. The OGZ_Simple deck (June 2026) describes a re-architected creative engine (fal.ai, 5 CD brains, 3-model comparison, 94 chains). The codebase sits between the two: it kept the TechDoc's governance/data architecture but adopted the OGZ_Simple visual stack (fal.ai + chain library) and a budget-driven model swap. Several "gaps" below are therefore really deviations where the implementation followed the newer direction rather than the older contract.

6. Cross-Cutting Discrepancies (Both Documents)

6.1 The "5 Creative Director brains" engine (OGZ_Simple) is not built as described

The OGZ_Simple deck centres on a creative engine that, for every brief, generates five captions from five Saudi creative philosophies — CD-01 Firaasa, CD-02 Metaphor, CD-03 Authenticity, CD-04 Heritage, CD-05 Paradox — then a router scores and picks the best, and a 3-model cross-compare (HUMAIN/ALLaM 34B vs Claude Sonnet vs GPT-4o) at /cross-compare feeds a learning loop toward an OGZ fine-tuned model.

OGZ_Simple claimIn code?What actually exists
5 distinct CD brains (Firaasa…Paradox)DIFFERENTA deterministic composition_matrix of 6 creative methods (Authenticity, Vulnerability, Heritage, Paradox, Diagnostic, Metaphor) selected via COO tool calls — not 5 independent generative "brains". No "Firaasa" routing.
3-model cross-compare + /cross-compare UIMISSINGNo 3-model side-by-side, no /cross-compare page, no human-preference training-pair capture.
ALLaM / HUMAIN 34B Saudi modelMISSINGNo ALLaM/HUMAIN integration anywhere.
94 visual chains (88 + 6), image+video, fal.aiPARTIALVisual-chain library + fal.ai exist (chains table, admin manager, video pipeline). The full 94-chain / 23-family catalogue should be verified for completeness against the deck.
"1,000 clicks → OGZ's own fine-tuned Saudi AI"MISSINGNo preference-pair logging or fine-tune pipeline. This is forward-looking roadmap, not built.

If OGZ_Simple represents the intended direction, the cross-compare/learning system and ALLaM are the largest unbuilt pieces of that vision. If the TechDoc remains the contract, these are out of Phase 1–3 scope and only the matrix/chains/fal.ai overlap matters.

6.2 Deliberate architecture decisions (documented in CHANGELOG)

  • fal.ai replaces Weavy.ai across the entire visual layer (image + video).
  • CEO → OpenAI, COO → DeepSeek (from Claude Sonnet/Haiku) due to Anthropic budget; CCO/Copilots unchanged.
  • negative_pattern_library → global_negative_patterns; leads table dropped (marketing form removed).
  • These are real and reasonable, but they diverge from the signed TechDoc and should be ratified as ADRs so milestone acceptance is not contested.

8. Recommended Priorities

  1. Close the Phase-1 launch blockers first: implement Stripe Checkout + webhook verification (unblocks revenue & SEC-10), and remediate the hard-coded secrets / ngrok URLs in the n8n flows (SEC-02). Promote A02 to a production webhook.
  2. Ratify the deviations: add ADR entries (and obtain client sign-off) for fal.ai-vs-Weavy and the OpenAI/DeepSeek model swap, so M1/M2 acceptance is not contested under §13.
  3. Add PostHog instrumentation to complete the Phase-1 stack and enable upgrade-funnel tracking.
  4. Confirm onboarding acceptance: validate the multi-stage onboarding flow against the client's "15-question" expectation.
  5. Phase 2 sequencing: finish Postiz auto-publish, then build the CIO analyzer (Gemini) and Business-Profile OAuth / Meta Insights ingestion.
  6. Phase 3: video chains are done — focus on the CARO Arabic-QC swap and a real competitor-analysis engine. Decide explicitly whether the OGZ_Simple cross-compare/ALLaM learning loop is in scope.
