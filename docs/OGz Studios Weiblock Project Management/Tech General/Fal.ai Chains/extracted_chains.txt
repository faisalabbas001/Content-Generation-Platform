How to use this document
This library is the canonical source for OpenClaw production chains. Every chain spec is structured identically so Weiblock can read them sequentially and insert into the Supabase prompt_templates table.
Each chain contains
Spec table with all metadata. Image generation prompt (the fal.ai instruction). Negative prompt (what fal.ai should avoid). Video variant motion prompt (additional instruction for fal.ai image-to-video models). Parameter mapping showing how BrandDNA fields resolve placeholders. Saudi cultural adaptation note. JSON specs for both image and video.
Image vs Video
Most chains support both formats. Static image generates first via FLUX, Kontext, or GPT Image 2. Video variant takes that image as the first frame and uses fal.ai image-to-video models (Kling v1.6 at $0.07/sec, Seedance 2.0 at $0.14/sec, Veo 3.1 at $0.40/sec) to add 5-7 seconds of motion. Dashboard offers static-or-video as per-chain choice.
BrandDNA integration
Parameters in curly braces ({like_this}) resolve at generation time from BrandDNA fields. The COO agent (Haiku 4.5) reads BrandDNA, fills placeholders, applies brand-specific creative direction persona, sends assembled prompt to fal.ai through n8n.

Part 3 — System migration spec
To make technique-organized chains plus image-to-video variants work end-to-end, six components need updates. None are breaking changes — all additive. Existing chains continue functioning during migration.
Migration 1 — Supabase chains table
Add five columns. Back-fill existing 26 chains with defaults.
ALTER TABLE chains ADD COLUMN technique_family TEXT NOT NULL DEFAULT 'TF01';
ALTER TABLE chains ADD COLUMN sectors_applicable TEXT[] NOT NULL DEFAULT '{}';
ALTER TABLE chains ADD COLUMN production_quality_tier TEXT NOT NULL DEFAULT 'universal';
ALTER TABLE chains ADD COLUMN visual_style_tags TEXT[] DEFAULT '{}';
ALTER TABLE chains ADD COLUMN video_variant JSONB DEFAULT NULL;
-- Back-fill existing 26 chains:
UPDATE chains SET sectors_applicable = ARRAY[sector]
  WHERE sectors_applicable = '{}';
UPDATE chains SET production_quality_tier =
  CASE WHEN fal_model LIKE '%pro%' THEN 'premium'
       WHEN fal_model LIKE '%ultra%' THEN 'luxury'
       ELSE 'universal' END
  WHERE production_quality_tier = 'universal';
Migration 2 — BrandDNA Family A schema
Add fields powering eligible-chains filtering.
// BrandDNA.A — additions
{
  "archetype_primary": "Caregiver | Everyman | Lover | Creator | Hero | ...",

  "asset_dependency_tolerance": "high | medium | low",

}
Migration 3 — brand_eligible_chains pre-computed view
New table holds pre-filtered chain list per brand. Updated at onboarding and when relevant BrandDNA fields change.
CREATE TABLE brand_eligible_chains (
  brand_id TEXT NOT NULL,
  chain_id TEXT REFERENCES chains(chain_id),
  eligibility_score NUMERIC(4,2),
  static_eligible BOOLEAN DEFAULT TRUE,
  video_eligible BOOLEAN DEFAULT FALSE,
  last_computed_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (brand_id, chain_id)
);
CREATE INDEX idx_brand_eligible_score
  ON brand_eligible_chains(brand_id, eligibility_score DESC);
Migration 4 — C-Suite agent updates
CEO agent now queries brand_eligible_chains rather than re-filtering every generation. Reads BrandDNA.A.visual_style_preference to weight technique families. Reads BrandDNA.A.format_preference to default static or video.
COO agent now reads chain.video_variant alongside chain.positive_prompt. When video requested, assembles both image prompt (generates first frame) and video motion prompt (extends to 5-7 second clip). Sends both to N8N-V01 sequentially.
CCO agent checks chain.compliance_level against BrandDNA.B.compliance_requirements. For TF23 Saudi UGC chains specifically, runs additional checks: modest fashion verification, single-gender group enforcement, face-visibility permission, no-religious-symbols verification.
Migration 5 — n8n workflow updates
N8N-V01 gains sync vs async branch determined by chain.video_variant presence and format selected. Static runs sync (8-25 sec). Video runs async with polling (45-90 sec).
// N8N-V01 routing pseudocode
if (request.format === 'video' && chain.video_variant) {
  // Step 1: Generate static image (sync)
  const image = await falApi.imageGenerate({
    model: chain.fal_model,
    prompt: assembledImagePrompt,
    reference_image: chain.reference_image
  });
  // Step 2: Static as first frame for video (async)
  const videoJob = await falApi.imageToVideoSubmit({
    model: chain.video_variant.fal_model,
    first_frame_url: image.cdn_url,
    motion_prompt: chain.video_variant.motion_prompt,
    duration_seconds: chain.video_variant.duration_seconds
  });
  // Step 3: Poll until complete
  const video = await pollUntilComplete(videoJob.id, 6);
  // Step 4: Reupload to Supabase Storage
  return await uploadToSupabase(video.cdn_url);
} else {
  // Sync image only
  return await falApi.imageGenerate({...});
}
Migration 6 — Content Maker dashboard
Dashboard gains 'Static or Video' toggle per chain selection. Default state determined by BrandDNA.A.format_preference and tier allocation. Cost displayed transparently on both options. Pro tier shows both freely; Starter shows video as locked except for occasion auto-triggers.
Migration timing
All six migrations can run in parallel and are fully additive. No downtime required. Existing client calendars continue running on existing chains during migration.
