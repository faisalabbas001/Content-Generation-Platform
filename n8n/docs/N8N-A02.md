# N8N-A02 — On-Demand Single Post (FAL AI)

The flow that fires when a client clicks **Generate Post** in
`/[slug]/on-demand`. Doc §3.2 + §5.1 + §10.1 — same agent chain as the
nightly batch (N8N-A01), but priority-routed and budgeted for a single post
with a **< 5 minute** SLA from click → caption + image visible in the
dashboard.

Workflow file: [`n8n/flows/N8N-A02_on_demand.json`](../flows/N8N-A02_on_demand.json)

---

## 1. Where it sits

```
[client]                                                      [openclaw]                             [n8n]                       [providers]
                                                              proxy.ts                               N8N-A02 (this flow)         FAL AI / Anthropic /
on-demand-form.tsx ──── POST /api/posts/on-demand ─────▶  validate +                                                              OpenAI / DeepSeek /
                                                          insert on_demand_requests ──▶  POST /webhook/openclaw-a02 ──▶  CEO ─▶ COO ─▶ DeepSeek ─▶ CCO ─▶ CEO ─▶ FAL ─▶ Storage
                                                                                                                                                                                        │
                                                          POST /api/webhooks/n8n  ◀───  callback when done  ◀──────────────────────────────────────────────────────────────────────────┘
```

Hard rule reminders this flow respects:
- **#1 CEO routes first.** Step 5 is `/api/agents/ceo/classify`. Nothing
  bypasses it.
- **#2 Memory Controller is the sole BrandDNA writer.** This flow only
  writes to `qa_review_queue`, `calendar_posts`, `on_demand_requests`. CEO
  may emit `memory_nominations`; the agent route enqueues them — n8n never
  touches Layer 1 directly.
- **#3 Arabic is never in image prompts.** Node 20 (Prepare FAL AI request)
  strips non-ASCII and only sends English descriptors. The Arabic
  `brand_name_ar` is composited *after* generation in node 23.
- **#4 No Weavy / FAL CDN URLs in DB.** The image is downloaded from FAL,
  optionally Sharp-overlaid, then re-uploaded to Supabase Storage. Only
  the Storage URL is persisted (`calendar_posts.storage_url`).

## 2. Quick start

### 2.1 Prerequisites

| Requirement                       | Why                                            |
|-----------------------------------|------------------------------------------------|
| n8n ≥ 1.100                       | Switch v3.2 + Supabase node v1 are required    |
| Supabase API credential           | Service-role REST credential (`supabaseApi`). The workflow uses n8n's first-party Supabase node (resource: `row`), which talks to PostgREST under the hood — no direct Postgres connection needed. |
| `NODE_FUNCTION_ALLOW_EXTERNAL=sharp` | Optional — enables the Arabic + watermark overlay. The Code node falls back to no overlay when sharp isn't allow-listed. |

### 2.2 n8n environment variables

Set these on the n8n host (UI: *Settings → Variables* on n8n Cloud, or
`environment` in your docker-compose file):

```
N8N_WEBHOOK_SECRET=<same hex string as OGz Studios .env>
OPENCLAW_API_BASE_URL=https://app.openclaw.ai
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service role key>
FAL_KEY=<fal.ai key>
FAL_MODEL_DEFAULT=fal-ai/flux/schnell
FAL_MODEL_PREMIUM=fal-ai/flux-pro/v1.1-ultra
```

The same secret is also read by `apps/web/src/lib/n8n-auth.ts` — both
sides verify the HMAC.

### 2.3 Supabase API credential

Create a credential named **`Supabase REST (service_role)`** of type
**Supabase API**. The workflow JSON references it by name on every
Supabase node, so this exact name matters.

| Field         | Value                                                 |
|---------------|-------------------------------------------------------|
| Host          | `https://<your-project-ref>.supabase.co`              |
| Service Role  | The `service_role` key from Project Settings → API    |

Why the Supabase node and not Postgres direct: PostgREST handles array →
`text[]`, object → `jsonb`, and timestamp coercion automatically, so we
don't have to hand-cast every column. The five Supabase nodes in the
workflow are configured as follows:

| Node                              | Operation | Table                |
|-----------------------------------|-----------|----------------------|
| Supabase: load brand_profiles     | get       | `brand_profiles`     |
| Supabase: insert qa_review_queue  | create    | `qa_review_queue`    |
| Supabase: insert calendar_posts   | create    | `calendar_posts`     |
| Supabase: mark delivered          | update    | `on_demand_requests` |
| Supabase: mark held               | update    | `on_demand_requests` |

The Supabase Storage upload (node 24) still uses the **HTTP Request**
node — n8n's Supabase node only handles the `row` resource and has no
Storage operations.

### 2.4 Import + activate

```bash
# 1. CLI import (developer machine):
n8n import:workflow --input=n8n/flows/N8N-A02_on_demand.json

# 2. Or UI: Workflows → Import from File.

# 3. Open the workflow, click the Webhook node and copy the Production URL.
#    e.g. https://n8n.example.com/webhook/openclaw-a02

# 4. Set OGz Studios env:
N8N_WEBHOOK_URL_A02=https://n8n.example.com/webhook/openclaw-a02

# 5. Toggle the workflow Active.
```

## 4. Authentication contract (HMAC, both directions)

Every cross-service call is signed with `N8N_WEBHOOK_SECRET`. Same scheme
both directions, so `lib/n8n-auth.ts` and `Verify HMAC + parse` (node 02)
implement the **same algorithm**:

| Header                  | What it is                                  |
|-------------------------|---------------------------------------------|
| `x-n8n-signature`       | `crypto.createHmac('sha256', secret).update(rawBody).digest('hex')` |
| `x-n8n-request-id`      | UUID v4. Server-side replay cache rejects duplicates within 10 min. |
| `x-n8n-timestamp`       | ISO-8601. Drift > 5 min rejects.            |
| `x-n8n-idempotency-key` | Stable per *logical* call. Server caches the response 5 min so retries are safe. |

In this workflow the idempotency key for each agent call is
`${request_id}:${step}` — e.g. `abc-…:ceo-classify`. That means a manual
retry of the workflow re-sends identical keys per step, and OGz Studios
returns the cached prior response instead of re-billing the LLM.

## 5. Route derivation table

CEO's `RoutingDecision` does NOT carry a per-post `route` field — it
carries `human_gate_required`, `confidence_mode`, `constraint_payload.watermark_required`.
Node 16 implements this table:

| Condition                                                                      | Route       |
|--------------------------------------------------------------------------------|-------------|
| `human_gate_required = true`                                                   | `hold`      |
| `confidence_mode ∈ {Cautious, Minimal}` OR `constraint_payload.watermark_required = true` | `watermark` |
| else                                                                           | `clean`     |

This matches Doc §3.2 (score ≥75 + no override → CLEAN; score 50-74 → WATERMARK;
score <50 OR override → HOLD) — the score-based mapping is what produces
the `confidence_mode` upstream, and `human_gate_required` covers all 11
override triggers.

## 7. FAL AI — model selection & prompt rules

```
first_ever_post = true                    → FAL_MODEL_PREMIUM   (flux-pro/v1.1-ultra)
image_model_pref ∈ {flux_ultra, fal_flux} → FAL_MODEL_PREMIUM
otherwise                                  → FAL_MODEL_DEFAULT   (flux/schnell)
```

`flux/schnell` runs in ~2 seconds and is what the SLA budget assumes.
`flux-pro/v1.1-ultra` runs ~12-20 seconds — only used when the brand needs
its first impression to land or when the CEO upgrade rule fires.

The prompt is composed in node 20 with **only ASCII** (any non-ASCII
character is stripped before assembly). Components:
- `hero_concept` — what's in the frame
- `Style: <style_descriptor>` — how it should look
- `Color palette: <hex,…>` — when ≥1 hex is set
- `Cultural guidance: <…>` — optional, English
- A sentence reserving the safe zone for the Arabic overlay

## 8. Operational notes

- **Default timeout per HTTP node** is 60 s. DeepSeek is 90 s, FAL gen is
  120 s. All HTTP + Postgres nodes have `retryOnFail=true, maxTries=2`.
  Final-fail bubbles to n8n's error handler — wire `N8N-S03` as the global
  Error Workflow when it ships.

- **Storage path is fixed** to
  `/clients/{brand_id}/calendars/{YYYY-MM}/{post_id}.jpg`. The CHECK
  constraint `no_weavy_urls` on `calendar_posts.storage_url` denies any
  URL containing `weavy.ai` — the Doc's Hard Rule #4 is enforced at the DB
  layer regardless of what the workflow does.

- **Sharp fallback.** If `NODE_FUNCTION_ALLOW_EXTERNAL=sharp` isn't set,
  node 23 logs that fact and forwards the un-overlaid FAL image. The post
  is still inserted; the Arabic + watermark overlay can be re-applied
  later. In production, set the env var.

- **No outbound work happens before the row exists.** OGz Studios inserts
  `on_demand_requests` (status=`queued`) BEFORE calling n8n. If n8n is
  unreachable, the row is flipped to `failed` and an `anomaly_records`
  row is written — no orphan trigger calls.

## 9. Troubleshooting

| Symptom                                              | Likely cause                                         | Fix                                                              |
|------------------------------------------------------|------------------------------------------------------|------------------------------------------------------------------|
| Webhook returns 401 `bad_signature`                  | `N8N_WEBHOOK_SECRET` differs between OGz Studios and n8n | Resync the env var on both sides. Restart n8n.                    |
| `deepseek_no_caption` thrown at node 12              | DeepSeek returned 0 captions                         | Check `usage_logs` for the upstream call; usually a token cap.    |
| Hold queued but caller sees `delivered`              | Race: callback ran before status update              | Bug — the workflow's connection map ensures the UPDATE runs before the callback. Re-check the imported graph. |
| FAL 401 / 422                                        | `FAL_KEY` missing or wrong endpoint name             | `curl https://fal.run/$FAL_MODEL_DEFAULT -H "Authorization: Key $FAL_KEY"`. |
| `no_weavy_urls` constraint violation                 | Workflow tried to insert a non-Storage URL           | Did node 25 run? Is `SUPABASE_URL` set correctly?                 |
| n8n CLI says `NOT NULL constraint failed: workflow_entity.active` | Importing on bare-metal n8n with strict SQLite | The shipped JSON sets `"active": false` — keep that field.        |
| Red banner "Could not find credential" on Supabase nodes | The `supabaseApi` credential isn't created yet | Settings → Credentials → New → Supabase API → name it exactly `Supabase REST (service_role)`. |
| `relation "<table>" does not exist` from a Supabase node | Schema isn't exposed to PostgREST OR the table name is misspelled in the workflow | All five tables live in `public`, which Supabase exposes by default. Re-import the workflow if you renamed a table. |
